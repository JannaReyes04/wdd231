# Music & Instrument Explorer — WDD 231 final project starter

This is a complete, editable student-project example. Review, personalize, and understand the implementation before submitting it as your individual work.

## Files
- `index.html`, `explore.html`, `favorites.html`: three required pages
- `form-action.html`: separate GET form results page
- `attributions.html`: source credits
- `styles/base.css`: responsive styles
- `scripts/*.js`: ES modules, DOM updates, filters, modal, localStorage, async fetch and try/catch
- `data/instruments.json`: 20 instrument records with multiple properties
- `images/*.svg`: lightweight original placeholder-style instrument cards and favicon

## Run locally
Use VS Code Live Server (right-click `index.html` → Open with Live Server), or run `python -m http.server 8000` from this folder. Do not open HTML directly using file:// because Fetch may be blocked.

## Before submission
1. Replace generic wording and author metadata with your own verified original content and authorship.
2. Replace the typographic SVG cards with optimized original/licensed instrument photos if desired; document any sources in `attributions.html`.
3. Replace `VIDEO_URL_HERE` in the footer of **all five** HTML files with your actual demonstration URL.
4. Publish in your own `wdd231/final` GitHub Pages path and update the Week 1 page's Final navigation link.
5. Validate HTML and CSS, run page audits and mobile Lighthouse (Accessibility, Best Practices, SEO all >=95), check contrast, navigation, form, dialog, and favorites. These checks have NOT been performed by this package builder.
6. Record your own 3–5 minute video with face and screen showing the JSON Fetch API, async/await with try/catch, and ES modules. Confirm all current course video requirements.
7. Check that every page is under 500 kB transferred from empty cache and has no horizontal overflow at 320px.

## Notes
This project uses no third-party CSS/JS frameworks. The form is demonstrative and does not transmit user data to a server. localStorage favorites are browser-specific. Images are lightweight vector designs with emoji; emoji appearance depends on the platform.
